## Шаг 1. Нативные PHP-шаблоны

### Принцип разделения

До рефакторинга в одном файле находилась и логика (обработка запросов, валидация, сортировка) и HTML-разметка. После разделения:

- **Логика** (`index.php`, `form.php`, `delete.php`) — только обработка данных, подготовка переменных, редиректы.
- **Представление** (`templates/native/*.php`) — только вывод HTML, никаких обращений к файлу данных или бизнес-логики.

### Функция `render()`

Для передачи данных из логики в шаблон реализована функция буферизованного рендеринга в `src/render.php`:

```php
<?php

/**
 * Рендерит нативный PHP-шаблон, оборачивая его в общий макет.
 *
 * @param string $template Имя шаблона (без пути и расширения).
 * @param array  $vars     Переменные, доступные в шаблоне.
 * @return void
 */
function render(string $template, array $vars = []): void
{
    extract($vars);        // превращает ключи массива в переменные

    ob_start();            // включаем буферизацию вывода
    require __DIR__ . '/../templates/native/' . $template . '.php';
    $content = ob_get_clean(); // захватываем вывод шаблона в $content

    require __DIR__ . '/../templates/native/layout.php'; // вставляем в макет
}
```

`ob_start()` и `ob_get_clean()` — механизм буферизации вывода. Вместо немедленного вывода в браузер PHP копит всё в буфер, затем `ob_get_clean()` забирает его содержимое как строку. Эта строка передаётся в `layout.php` через переменную `$content`.

### Общий макет `templates/native/layout.php`

Содержит HTML-обёртку, навигацию и CSS, а переменную `$content` выводит в нужном месте:

### Вспомогательные функции `src/helpers.php`

Небольшие функции для шаблонов, которые не являются бизнес-логикой, но нужны для корректного отображения данных:

```php
<?php

/**
 * Переводит код категории в читаемое название.
 *
 * @param string $category Код категории
 * @return string Название на русском
 */
function categoryLabel(string $category): string
{
    return match ($category) {
        'health'       => 'Здоровье',
        'sport'        => 'Спорт',
        'learning'     => 'Обучение',
        'productivity' => 'Продуктивность',
        'other'        => 'Другое',
        default        => $category,
    };
}

/**
 * Возвращает HTML-бейдж для статуса выполнения привычки.
 *
 * @param string $status Код статуса
 * @return string HTML строка с бейджем
 */
function statusBadge(string $status): string
{
    [$label, $class] = match ($status) {
        'completed' => ['✅ Выполнено', 'badge-success'],
        'partial'   => ['🔶 Частично',  'badge-warning'],
        'skipped'   => ['❌ Пропущено', 'badge-danger'],
        default     => [$status, 'badge-default'],
    };
    return '<span class="badge ' . $class . '">' . htmlspecialchars($label) . '</span>';
}

/**
 * Генерирует ссылку для сортировки по столбцу с указанием направления.
 *
 * @param string $field   Поле для сортировки
 * @param string $label   Текст ссылки
 * @param string $current Текущее активное поле сортировки
 * @param string $dir     Текущее направление ('asc' или 'desc')
 * @return string HTML-ссылка
 */
function sortLink(string $field, string $label, string $current, string $dir): string
{
    $newDir = ($field === $current && $dir === 'asc') ? 'desc' : 'asc';
    $arrow  = '';
    if ($field === $current) {
        $arrow = $dir === 'asc' ? ' ▲' : ' ▼';
    }
    $url = '?sort=' . urlencode($field) . '&dir=' . $newDir;
    return '<a href="' . $url . '">' . htmlspecialchars($label) . $arrow . '</a>';
}
```

### Вызов из логики

Файл `index.php` после рефакторинга занимается только подготовкой данных и вызовом `render()`:

```php
<?php
session_start();
require_once 'src/classes.php';
require_once 'src/helpers.php';
require_once 'src/render.php';

$storage = new HabitStorage('data.json');
$entries = $storage->loadAll();

$sort    = $_GET['sort'] ?? 'date';
$dir     = $_GET['dir']  ?? 'desc';
$allowed = ['date', 'habit_name', 'category', 'status', 'duration_min', 'created_at'];

if (!in_array($sort, $allowed, true)) $sort = 'date';
if (!in_array($dir, ['asc', 'desc'], true)) $dir = 'desc';

usort($entries, function ($a, $b) use ($sort, $dir) {
    $cmp = strcmp($a->$sort, $b->$sort);
    return $dir === 'asc' ? $cmp : -$cmp;
});

$flash = $_SESSION['flash'] ?? null;
unset($_SESSION['flash']);

render('list', [
    'title'   => 'HabitFlow — Список привычек',
    'entries' => $entries,
    'sort'    => $sort,
    'dir'     => $dir,
    'flash'   => $flash,
]);
```

## Шаг 2. Twig

### Установка

Twig устанавливается через Composer. В корне проекта создан файл `composer.json`:

```json
{
    "require": {
        "twig/twig": "^3.0"
    }
}
```

Установка выполняется командой в терминале:

```bash
composer install
```

После этого появляется папка `vendor/` с библиотекой и файл `vendor/autoload.php` для автозагрузки классов.

### Инициализация в `src/twig.php`

```php
<?php

require_once __DIR__ . '/../vendor/autoload.php';

/**
 * Создаёт и настраивает окружение Twig с зарегистрированными фильтрами.
 *
 * @return \Twig\Environment
 */
function createTwig(): \Twig\Environment
{
    $loader = new \Twig\Loader\FilesystemLoader(__DIR__ . '/../twig-templates');
    $twig   = new \Twig\Environment($loader, ['cache' => false]);

    // регистрация кастомных фильтров
    $twig->addFilter(new \Twig\TwigFilter('format_category', function (string $category): string {
        return match ($category) {
            'health'       => 'Здоровье',
            'sport'        => 'Спорт',
            'learning'     => 'Обучение',
            'productivity' => 'Продуктивность',
            'other'        => 'Другое',
            default        => $category,
        };
    }));

    $twig->addFilter(new \Twig\TwigFilter('format_status', function (string $status): string {
        return match ($status) {
            'completed' => '✅ Выполнено',
            'partial'   => '🔶 Частично',
            'skipped'   => '❌ Пропущено',
            default     => $status,
        };
    }));

    $twig->addFilter(new \Twig\TwigFilter('format_duration', function (string $minutes): string {
        $min = (int) $minutes;
        if ($min < 60) return $min . ' мин.';
        $h = intdiv($min, 60);
        $m = $min % 60;
        return $m > 0 ? "{$h} ч {$m} мин." : "{$h} ч";
    }));

    return $twig;
}
```

`FilesystemLoader` указывает Twig папку с шаблонами. `Environment` — основной объект, через который вызывается рендеринг шаблонов.

### Вызов из логики (Twig-версия)

Файл `index_twig.php` аналогичен `index.php`, но вместо `render()` использует Twig:

```php
<?php
session_start();
require_once 'src/classes.php';
require_once 'src/twig.php';

$storage = new HabitStorage('data.json');
$entries = $storage->loadAll();

$sort    = $_GET['sort'] ?? 'date';
$dir     = $_GET['dir']  ?? 'desc';
$allowed = ['date', 'habit_name', 'category', 'status', 'duration_min', 'created_at'];

if (!in_array($sort, $allowed, true)) $sort = 'date';
if (!in_array($dir, ['asc', 'desc'], true)) $dir = 'desc';

usort($entries, function ($a, $b) use ($sort, $dir) {
    $cmp = strcmp($a->$sort, $b->$sort);
    return $dir === 'asc' ? $cmp : -$cmp;
});

$flash = $_SESSION['flash'] ?? null;
unset($_SESSION['flash']);

$twig = createTwig();
echo $twig->render('list.twig', [
    'entries' => $entries,
    'sort'    => $sort,
    'dir'     => $dir,
    'flash'   => $flash,
]);
```

### Синтаксис Twig vs нативный PHP

| Действие         | Нативный PHP                      | Twig                                     |
|------------------|-----------------------------------|------------------------------------------|
| Вывод переменной | `<?= $var ?>`                     | `{{ var }}`                              |
| Условие          | `<?php if (...): ?>`              | `{% if ... %}`                           |
| Цикл             | `<?php foreach (...): ?>`         | `{% for item in items %}`                |
| Экранирование    | `htmlspecialchars($v)`            | автоматически при `{{ v }}`              |
| Фильтр           | вызов функции `categoryLabel($v)` | `{{ v \| format_category }}`             |
| Комментарий      | `<?php // ... ?>`                 | `{# ... #}`                              |
| Наследование     | `ob_start()` / `ob_get_clean()`   | `{% extends %}` / `{% block %}`          |

Twig автоматически экранирует все переменные при выводе через `{{ }}` — не нужно вручную писать `htmlspecialchars()` в каждом месте шаблона.

## Шаг 3. Кастомные фильтры Twig

Зарегистрированы три собственных фильтра в `src/twig.php`:

### Фильтр `format_category`

Переводит код категории привычки в читаемое название на русском языке:

```php
$twig->addFilter(new \Twig\TwigFilter('format_category', function (string $category): string {
    return match ($category) {
        'health'       => 'Здоровье',
        'sport'        => 'Спорт',
        'learning'     => 'Обучение',
        'productivity' => 'Продуктивность',
        'other'        => 'Другое',
        default        => $category,
    };
}));
```

Использование в шаблоне:

```twig
{{ entry.category | format_category }}
{# 'sport' → 'Спорт' #}
```

### Фильтр `format_status`

Добавляет эмодзи-иконку к статусу выполнения привычки:

```php
$twig->addFilter(new \Twig\TwigFilter('format_status', function (string $status): string {
    return match ($status) {
        'completed' => '✅ Выполнено',
        'partial'   => '🔶 Частично',
        'skipped'   => '❌ Пропущено',
        default     => $status,
    };
}));
```

Использование в шаблоне:

```twig
{{ entry.status | format_status }}
{# 'completed' → '✅ Выполнено' #}
```

### Фильтр `format_duration`

Переводит количество минут в читаемый формат «X ч Y мин.»:

```php
$twig->addFilter(new \Twig\TwigFilter('format_duration', function (string $minutes): string {
    $min = (int) $minutes;
    if ($min < 60) return $min . ' мин.';
    $h = intdiv($min, 60);
    $m = $min % 60;
    return $m > 0 ? "{$h} ч {$m} мин." : "{$h} ч";
}));
```

Использование в шаблоне:

```twig
{{ entry.duration_min | format_duration }}
{# '30'  → '30 мин.'   #}
{# '90'  → '1 ч 30 мин.' #}
{# '120' → '2 ч'       #}
```

## Контрольные вопросы

### 1. В чём отличие нативных PHP-шаблонов от Twig? Преимущества и недостатки каждого подхода

**Нативные PHP-шаблоны** — обычные `.php`-файлы, в которых PHP-код перемежается с HTML.

Преимущества: не требуют установки дополнительных библиотек, полный доступ ко всем функциям PHP, нет накладных расходов на компиляцию шаблонов.

Недостатки: ничто не мешает написать в шаблоне бизнес-логику — обращение к файлу данных, сложные вычисления. Дисциплина разделения держится только на договорённости разработчика с самим собой. Нет автоматического экранирования — `htmlspecialchars()` нужно писать вручную в каждом месте вывода.

**Twig** — отдельный язык шаблонов со своим синтаксисом (`{{ }}`, `{% %}`).

Преимущества: автоматическое экранирование всех переменных защищает от XSS по умолчанию. Наследование шаблонов (`extends`, `block`) позволяет не дублировать макет страницы. Синтаксис намеренно ограничен — нельзя написать сложную логику прямо в шаблоне. Кастомные фильтры позволяют переиспользовать логику форматирования по всем шаблонам.

Недостатки: требует установки через Composer, добавляет зависимость в проект. Шаблоны компилируются в PHP-код, что даёт небольшой прирост кэша, но требует настройки папки кэша. Синтаксис Twig нужно изучать отдельно.

---

### 2. Зачем разделять логику и представление? Какие проблемы возникают если их смешивать

Когда логика и HTML находятся в одном файле — при изменении внешнего вида приходится редактировать тот же файл, где находится обработка данных, и наоборот. Это увеличивает риск случайно сломать что-то несвязанное.

Конкретные проблемы при смешивании: тяжело тестировать логику отдельно от HTML; один и тот же макет приходится копировать в каждый файл, и при изменении шапки сайта нужно редактировать все файлы; шаблон становится нечитаемым, когда между HTML-тегами стоят длинные блоки PHP-кода с сортировкой и валидацией.

После разделения `index.php` занимается только подготовкой данных и заканчивается одним вызовом `render()` или `$twig->render()` — шаблон получает уже готовые данные и только выводит их.

### 3. Что такое наследование шаблонов в Twig? Как работают `{% extends %}` и `{% block %}`

Наследование позволяет определить общую структуру страницы один раз в базовом шаблоне, а в дочерних шаблонах заменять только нужные части.

`layout.twig` объявляет блоки-заглушки:

```twig
{% block title %}HabitFlow{% endblock %}
{% block content %}{% endblock %}
```

`list.twig` расширяет макет и заполняет блоки своим содержимым:

```twig
{% extends 'layout.twig' %}

{% block title %}HabitFlow — Список привычек{% endblock %}

{% block content %}
    ...таблица записей...
{% endblock %}
```

При рендеринге Twig берёт `layout.twig` целиком и вставляет содержимое каждого блока из `list.twig` на место соответствующей заглушки. Навигация, стили, шапка — всё это в `layout.twig` и автоматически присутствует на каждой странице без копирования. В нативной реализации то же самое достигается через `ob_start()` / `ob_get_clean()` вручную.
